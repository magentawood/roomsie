## 2026-10-25 — T-05: Google sign-in works

- **What:** [#131](https://github.com/magentawood/roomsie/pull/131) adds Google sign-in on the web and `GET /v1/me` in the API. `jose` verifies the Firebase ID token with the cached keys of Google. The first sign-in makes the `users` row. A revoked token gets 401, and a user who is not active gets 403.
- **Why:** ADR-0007 makes the Bearer token the only auth mechanism. The grill added the status check, because a suspended user can get a new token.
- **Dead ends:**
  - With the default `now()`, the first token got 401 against its own new row. The row now starts `tokens_valid_after` at the `auth_time` of that token.
  - The first check compared `iat`. Firebase refreshes the token each hour with a new `iat`, so a revoked session came back. The check now compares `auth_time`, the time of the sign-in.
  - jose gives a plain `JOSEError` when Google's key server fails. A first version turned it into 401. The API now gives 401 only for token errors.
  - Port 8080 on the laptop had a different program, so the local API ran on 8081.
- **Next:** apply the migrations to the live database, so `/v1/me` works in production. Put the four `NEXT_PUBLIC_FIREBASE_*` values in Vercel. T-16a, T-17 and T-33 can start.
