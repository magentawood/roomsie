# Journal: 2026-10

## 2026-10-03 — T-02: the monorepo exists

- **What:** [#94](https://github.com/magentawood/roomsie/pull/94) makes the monorepo. `pnpm dev` starts the web app and the API. `pnpm test` starts a local Postgres 17 in Docker, makes a disposable database, and runs the tests. The API serves each route below `/v1`, and it generates its OpenAPI document from the Zod schemas of `packages/contract`.
- **Why:** ADR-0010 sets pnpm workspaces and Turborepo. ADR-0003 sets two apps that deploy independently. The grill of T-02 set the remaining choices: `tsx` for development, `tsup` for the build, postgres.js with prepared statements off for the Supabase pooler, and `pnpm db:up` as a separate command.
- **Design change:** the user said that the V3 prototype has no value at this time. The launch look comes from the Figma designs, which are not available at this time. PD12, PD5, the standards, the working docs, D-01 and T-23a changed. The prototype is in `docs/archive/`.
- **Dead ends:**
  - pnpm 12 does not run through Corepack, so the repo pins pnpm 11.28.2.
  - TypeScript 7 breaks typescript-eslint, so the repo uses TypeScript 6.0.
  - Turborepo writes an `AGENTS.md` when it finds an agent. `turbo.json` turns this off, because `CLAUDE.md` is the only entry point.
  - The plan generator kept the old checklist lines next to the new lines. The fix was to change the old lines in the notes first, then run the generator.
- **Next:** T-03 adds the CI gate. T-04 deploys the two apps. T-06 adds the first migrations.

## 2026-10-06 — T-04: the web and the API are live in Mumbai

- **What:** [#110](https://github.com/magentawood/roomsie/pull/110) puts the API on AWS Lightsail containers in `ap-south-1`. A GitHub workflow builds the Docker image and deploys it after each merge that changes the API. Vercel publishes the web from `main` through its Git link, and the web reads the API address from `NEXT_PUBLIC_API_URL`.
- **Why:** ADR-0009 needs the API and the database in one region. Supabase is in AWS Mumbai, and Lightsail is in the same AWS region.
- **Host change:** Fly refused the first deploy: "Region bom is deprecated and cannot have new resources provisioned". Fly has no Indian region now. The user chose Lightsail in Mumbai, not all of roomsie in Singapore. ADR-0009 has the change and a Superseded line. The Fly app is deleted. It never ran a machine, so it cost nothing.
- **Dead ends:**
  - The root `prepare` script calls `git`, and the image has no `git`. The image install skips scripts.
  - A new AWS account could not make a container service at first ("maximum limit of Lightsail Container Services"). It worked some minutes later.
  - Lightsail has no secret store. The API secrets are GitHub secrets, and the workflow gives them to each deployment.
- **Next:** T-25 (uptime and spend alerts) and T-40 (nightly backups) can start. Previews do not call the production API. The team examines this again after the launch.

## 2026-10-08 — T-03: each pull request runs the CI gate

- **What:** [#112](https://github.com/magentawood/roomsie/pull/112) adds `ci.yml`. Its `check` job runs typecheck, lint, build and the API tests against a Postgres 17 service container. Its `secrets` job runs gitleaks on the full history. `pnpm secrets` scans the commits of a branch before its pull request. The `protect-main` ruleset now targets `main`. It needs a pull request, one approval and the three checks, and nobody can bypass it.
- **Why:** ADR-0013 needs the checks and the tests on each pull request. The grill changed ADR-0016: gitleaks runs before each pull request and in CI, not before each commit.
- **Dead ends:**
  - The old `protect-main` ruleset had an empty branch list, so it protected no branch.
  - Turborepo 2 gave the tests no `TEST_DATABASE_URL`, because `turbo.json` did not name it. The tests used the same address as a default, so nothing failed. The second review round found it.
  - The gitleaks GitHub Action needs a licence key for an organisation repo. CI runs the Docker image.
- **Open:** the repo is public, but `CONTEXT.md` says that it is private, and its history holds a session transcript with personal data. On the free plan, a private repo has no rulesets. The owners must decide.
- **Next:** add `TURBO_TOKEN` and `TURBO_TEAM` for the remote cache. T-07, T-25 and T-40 can start.

## 2026-10-08 — F-02: roomsie.in is live

- **What:** [#113](https://github.com/magentawood/roomsie/pull/113) puts the web on roomsie.in and the API on `api.roomsie.in`. `www.roomsie.in` and `roomsie.vercel.app` redirect to roomsie.in. The DNS is on Cloudflare, with each record "DNS only". The API accepts browser calls only from `https://roomsie.in`.
- **Why:** one address for the site and the login. ADR-0009 now has the reasons for Cloudflare DNS.
- **Dead ends:**
  - Cloudflare offered "Transfer a domain". A GoDaddy domain cannot move to a different registrar for 60 days. The fix: "Connect a domain", which changes only the name servers.
  - GoDaddy had put roomsie.in on "Registrar Hold" (`clientHold`) since 12 September. The domain did not work, and no setting could change. GoDaddy support removed the hold.
  - The deploy user could not make a certificate. Its policy now also allows `lightsail:*Certificate*`.
- **Next:** T-05 adds roomsie.in to the authorized domains of Firebase.
