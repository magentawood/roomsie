# Journal: 2026-11

## 2026-11-01 — T-08: the Form A contract

- **What:** [#184](https://github.com/magentawood/roomsie/pull/184) adds the Form A schema and the results union to `packages/contract`, with the first unit tests of the package. Each slot has a value and a source: stated, default or empty. Each enum of Form A has `unclear`. The weight of a must-have can also be `unclear`, and then it has no effect on the results. A result has `kind: "person"` or `kind: "listing"`, and the labels of PD3a.
- **Why:** T-09, T-11, T-12, T-14, T-15 and T-48 need one form to build against. Two copies of Form A were the drift that T-08 must stop.
- **Decisions:** the user does not want the system to guess a value. Thus, PD15 has no `inferred` source. An unclear weight waits for the answer of the person to two chips. `unclear` is only in the chat, so a card never shows it. PD3b, PD6c, `api.md` and three docs lose the old inferred text.
- **Dead ends:**
  - Zod `.default({})` on a nested object gives `{}` with no slots in it, because a default does not parse. `.prefault({})` parses the value.
  - A helper that built the lifestyle slots from the keys gave each question the answers of all questions. A `satisfies` check on the list of eight keeps the types, and fails when a ninth question comes.
  - Review round 1 added `version: 1` and strict keys. A misspelled slot key had read as empty with no error.
  - In the first full test run, two migration tests failed under load. They passed alone and on the next full run.
- **Next:** T-14 changes the match query to this Form A, with the must-have filters of PD3a. T-12 fills it from the chat.
