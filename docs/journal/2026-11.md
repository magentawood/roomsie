## 2026-11-01 — T-08: the Form A contract

- **What:** [#184](https://github.com/magentawood/roomsie/pull/184) adds the Form A schema and the results union to `packages/contract`, with the first unit tests of the package. Each slot has a value and a source: stated, default or empty. Each enum of Form A has `unclear`. The weight of a must-have can also be `unclear`, and then it has no effect on the results. A result has `kind: "person"` or `kind: "listing"`, and the labels of PD3a.

  - A helper that built the lifestyle slots from the keys gave each question the answers of all questions. A `satisfies` check on the list of eight keeps the types, and fails when a ninth question comes.
  - Review round 1 added `version: 1` and strict keys. A misspelled slot key had read as empty with no error.
  - In the first full test run, two migration tests failed under load. They passed alone and on the next full run.

## 2026-11-02 — T-11: the model wrapper

- **What:** [#186](https://github.com/magentawood/roomsie/pull/186) adds `apps/api/src/models/`, the only code that calls a model. It sends the chat request of the OpenAI format with `fetch`, to DeepSeek first and to Gemini as the fallback. Each attempt writes the event `model_called` with the tokens, the cached tokens, the time and the outcome. With `POST /v1/admin/model-check`, a moderator checks the two keys after a deploy.
- **Why:** T-12, T-13 and T-38 need one way to call a model. PD5 needs the tokens of each session to give the cost of an interview.
- **Decisions:**
  - The record of each call is an analytics event and one log line, with no text of the user or the model. The user decided this in the grill.
  - A 4xx from DeepSeek other than 429, such as a bad key or an empty balance, also goes to Gemini, and the module reports it. The user decided this after review round 2.
  - The first word of a model name selects the vendor. With a name of a third vendor, the API does not start.
  - In the extra review round, two reviewers did not agree. The user kept `z.int().min(0)` written out, as in the rest of the contract, and kept the real analytics database in the test of the check route.
- **Dead ends:**
  - In round 1, a bad key gave a 500 from the check route, because an attempt could throw. Now an attempt never throws, and each final failure is `ModelUnavailable`.
  - A timeout or a broken connection can also come while the body arrives. Both counted as an answer that is not valid, so DeepSeek got a second attempt. Now only a `SyntaxError` of the body is an answer that is not valid.
  - Each model reported its 4xx, so a 4xx of Gemini was reported two times. Now only the first attempt of DeepSeek reports it.
- **Next:** the live check of the two keys after the deploy. T-12 builds the extractor on `models.json()`.

## 2026-11-02 — T-14: the match query

- **What:** [#187](https://github.com/magentawood/roomsie/pull/187) adds `POST /v1/results`. A guest or a signed-in person sends a Form A and gets people or listings, in the Best Matches order of PD3a. Each card has "Best match" and "Didn't say". An empty search also gives the next budget band and two neighbours of the area group. Each page fires `results_shown`.
- **Why:** the results panel of T-15 needs one search to call. The draft match query of T-06 used an old Form A and a score that PD3a removed.
- **Decisions:**

  - Form B breaks a tie: one point for each topic where the two people have a same-kind note above the floor. PD3a has the rule now.
  - An empty search gives cards for each relaxed search in the same response.
  - "Best match" needs a full match and three preferences that apply to the card, all met. A searcher does not see their own listings.

  - A `git checkout` in a mutation check undid an uncommitted rewrite. A copy from just before the check brought it back.

  - The added review round found an id tie-break on an offset page, which `database.md` does not permit. The id went.
