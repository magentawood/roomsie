# The eval of November 2026

**Date:** 2026-11-04 · **Status:** the results of T-27, input to check 6 of [PD11](../decisions/pd-11-launch.md)
**Question:** How well do the extractor and the router read the 50 eval sentences on each model, and which changes fix the misses?

---

## The headline

1. **DeepSeek passes check 6 of PD11 after the fixes.** In the last run, it got 99% of the labelled slots right (472 of 475), and it marked 97% of the vague slots `unclear` (28 of 29). No vague slot got a value.
2. **Gemini alone does not pass check 6.** It gets 99% of the slots right, but it marks only 57% of the vague slots `unclear`, and it fills a vague slot with a value in each repeat. Gemini gives no token probabilities, so code cannot stop these values ([PD7](../decisions/pd-07-models.md)). Gemini is only the fallback.
3. **The router now gives the language of the person.** On DeepSeek, the language of the router was right in 57% of the turns before, and in 100% after. Before, it called each Hindi or Marathi message with an English word `mixed`, and the reply came in Hindi.
4. **The threshold of the extractor changes almost no score,** so `ASSISTANT_MIN_PROBABILITY` stays 0.8 (see [the threshold](#the-threshold)).
5. **DeepSeek is slow in its peak hours.** The 95th percentile of its extractor is at or near the timeout of 10 seconds. Some turns get no answer from DeepSeek, and live, Gemini answers them.

## The steps, and what each one gave

Each step was measured on its own. A replay scores the answers of a run again through the code of a step, with no model call. A change of a prompt needs a new run.

| Step | Measured on | DeepSeek | Gemini |
|---|---|---|---|
| **1. The copy check and the dates.** A copied word with a Marathi ending counts, with the endings of the area catalogue (PC-09). The date parser reads "पुढच्या महिन्याच्या शेवटी" and "पुढच्या आठवड्यापासून". | A replay of the first run | Slots right 93% → 99%, Marathi 79% → 98% | Slots right 95% → 98%, Marathi 90% → 98% |
| **2. The prompts.** The router gives the main language and the main script. The extractor leaves out each lifestyle and must-have key that a message does not name. A choice of values, "any", or a question is `unclear`. One word can fill two slots, as "student". | The second run | Vague slots unclear 92% → 97%. Unclear with no label 36.7 → 1. Router language 57% → 99% | Vague slots unclear 33% → 60%. Vague slots with a value 3.7 → 1. Unclear with no label 56.3 → 2.3. Router language 53% → 96% |
| **3. The joined spelling "विलेपार्ले".** The seed knew only "विले पार्ले". | A replay of the second run | Marathi 98% → 100% | Marathi 98% → 100% |
| **4. The router shape.** The JSON shape of the router no longer offers the script `mixed`. | The last run | Router language 99% → 100%, script 100% | Router language 96% → 95%, script 95% → 94% |

- No step lowered a score that it changes on DeepSeek.
- In step 4, the Marathi script of Gemini went down from 86% to 82%. That is 2 turns, or 3 turns from the third run. Gemini misses m04 and m09 in each run. Its other Marathi misses of the script were 2, 1, 0 and 3 turns in the four runs. Its Hinglish language went down from 94% to 93%: h17 was `mixed` in 1 of 3 repeats. The user kept the change ([the spec of T-27](../plan/tasks/T-27%20Eval%20run.md)).
- Step 1 has the copy check and the date forms in one replay. Step 2 has the two prompts and the new h15 and m11 in one run. The router prompt changes only the scores of the router, and the extractor prompt only the scores of the extractor.
- Only e03 tests the rule "one word can fill two slots". The user kept the rule ([the spec of T-27](../plan/tasks/T-27%20Eval%20run.md)).
- No prompt holds a sentence of the set.

**Why the first run missed the Marathi areas.** DeepSeek copied "ठाणे वेस्ट" from "ठाणे वेस्टमध्ये". The copy check wanted whole words, so it dropped the area. Gemini often copied the ending too.

**Why so many slots were `unclear` with no label.** The JSON shape of the prompt shows each lifestyle key, so a message about flatmates gave all eight keys as `unclear`. The assistant asks these questions later anyway.

**Runs with the same extractor.** The third run had the code of step 3, and the last run differs from it only in the router shape. On DeepSeek, the third run got 100% of the slots and of the vague slots, and the last run 99% and 97%. In the last run, e02 got a made-up room type in 3 of 3 repeats, so the made-up values went from 0.3 to 1. e08, e12, h06 and h17 each missed one slot in 1 of 3 repeats. The extractor did not change, so a gap of this size between two runs is noise.

## The threshold

- In the last run, the sweep gives the same scores from 0.5 to 0.95 on both models. In the first run, 0.95 lost one slot on DeepSeek.
- DeepSeek gives a high token probability to nearly each value. The vague slots come as `unclear` from the model, not from the gate.
- A threshold changes a value only when its probability is low, and this set has almost none. `ASSISTANT_MIN_PROBABILITY` stays 0.8. A larger set can show a different value ([PD7](../decisions/pd-07-models.md) asks for 200 to 300 sentences).

## What is still open

- **Gemini as the fallback.** It fills a vague slot in each repeat: h16 ("रूम या पीजी कुछ भी चलेगा") gives `room` or `pg`. Live, the fallback answers when the first attempt of DeepSeek fails: in 5 of 150 turns of the extractor in the last run, and in 10 of 150 in the first. F-10 decides if check 6 applies to the fallback ([PD11](../decisions/pd-11-launch.md)).
- **The time of DeepSeek.** The 95th percentile of the extractor is 9.3 to 10 seconds in its peak hours, at or near the timeout. A live turn then goes to Gemini. [T-61](eval-2026-11-composer.md) measured the composer.
- **The misses of the last run.**
  - DeepSeek: e02 gets the room type `private` from "a room in a shared flat" (3 of 3). m11 gets no answer in 1 of 3.
  - Gemini: e03 has no `your_days` (3 of 3). h17 makes "tidy log hi chahiye" `unclear`, not a dealbreaker (3 of 3). e12, h13, m11 and m12 leave a vague slot empty, not `unclear`. e09 gets the food `veg` from "PG … with food" in 1 of 3.
- **The router.** Gemini calls m04 and m09, which are Devanagari Marathi, `latin` in each run, and in the last run also m06 (2 of 3) and m07 (1 of 3). It calls h12, which is heavy Hinglish in Latin script, `english`, and m15, which is heavy Marathi code-mix, `hindi`.
- **The set.** It has 50 sentences, and only searches. [T-61](eval-2026-11-composer.md) added the other bands.
