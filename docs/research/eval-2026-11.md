# The eval of November 2026

**Date:** 2026-11-04 · **Status:** the results of T-27, input to check 6 of [PD11](../decisions/pd-11-launch.md)
**Question:** How well do the extractor and the router read the 50 eval sentences on each model, and which changes fix the misses?

---

## The headline

1. **DeepSeek passes check 6 of PD11 after the fixes.** In the last run, it got each labelled slot right (477 of 477), and it marked each vague slot `unclear` (30 of 30). It made up one value in 150 turns.
2. **Gemini alone does not pass check 6.** It gets 99% of the slots right, but it marks only 57% of the vague slots `unclear`, and it fills 3 of them with a value. Gemini gives no token probabilities, so code cannot stop these values ([PD7](../decisions/pd-07-models.md)). Gemini is only the fallback.
3. **The router now gives the language of the person.** On DeepSeek, the language of the router was right in 57% of the turns before, and in 99% after. Before, it called each Hindi or Marathi message with an English word `mixed`, and the reply came in Hindi.
4. **The threshold of the extractor changes almost no score.** In the last run, each threshold from 0.5 to 0.95 gives the same scores on both models. In the first run, only 0.95 lost one slot on DeepSeek. `ASSISTANT_MIN_PROBABILITY` stays 0.8.

## The changes, and what each one gave

Each step was measured on its own. A replay scores the answers of a run again through new code, with no model call. A change of a prompt needs a new run.

- Step 1 has the copy check and the date forms in one replay.
- Step 2 has the two prompts, and the new h15 and m11, in one run. The router prompt changes only the scores of the router, and the extractor prompt only the scores of the extractor. The score of the vague slots in step 2 also has the new h15 and m11.
- Only e03 tests the rule "one word can fill two slots".

| Change | Measured on | DeepSeek | Gemini |
|---|---|---|---|
| **1. The copy check and the dates.** A copied word with a Marathi ending counts, with the endings of the area catalogue (PC-09). The date parser reads "पुढच्या महिन्याच्या शेवटी" and "पुढच्या आठवड्यापासून". | A replay of the first run | Slots right 91% → 97%, Marathi 75% → 93% | Slots right 95% → 98%, Marathi 90% → 98% |
| **2. The prompts.** The router gives the main language and the main script. The extractor leaves out each lifestyle and must-have key that a message does not name. A choice of values, "any", or a question is `unclear`. One word can fill two slots, as "student". | A new run | Slots right 97% → 99%. Vague slots unclear 80% → 93%. Unclear with no label 110 → 3. Router language 57% → 99% | Slots right 98% → 98%. Vague slots unclear 33% → 60%. Unclear with no label 169 → 7. Router language 53% → 96% |
| **3. The joined spelling "विलेपार्ले".** The seed knew only "विले पार्ले". | A replay of the second run | Marathi 97% → 99% | Marathi 98% → 100% |

No step lowered the score of a language on a model. Each rule is a general rule: no prompt holds a sentence of the set.

**The second run and the last run.** They had the same prompts, and the last run also had the change of the seed. DeepSeek marked 93% of the vague slots `unclear` in the second run and 100% in the last run, with no change that touches them. A gap of this size between two runs is noise.

**Why the first run missed the Marathi areas.** DeepSeek copied "ठाणे वेस्ट" from "ठाणे वेस्टमध्ये". The copy check wanted the copied words as whole words of the message, so it dropped the area. Gemini often copied the ending too, so it lost fewer areas.

**Why so many slots were `unclear` with no label.** The JSON shape of the prompt shows each lifestyle key. When a message named flatmates, the models gave each of the eight keys as `unclear`. The assistant asks these questions later anyway, so the cost was noise, not a wrong value.

## The threshold

- In the last run, the sweep gives the same scores from 0.5 to 0.95 on both models. In the first run, 0.95 lost one slot on DeepSeek.
- DeepSeek gives a high token probability to nearly each value. The vague slots come as `unclear` from the model, not from the gate.
- A threshold changes a value only when its probability is low, and this set has almost none. `ASSISTANT_MIN_PROBABILITY` stays 0.8. A larger set can show a different value ([PD7](../decisions/pd-07-models.md) asks for 200 to 300 sentences).

## What is still open

- **Gemini as the fallback.** It fills a vague slot in 3 of 30 cases, all h16 ("रूम या पीजी कुछ भी चलेगा" gives `room` or `pg`). The fallback answers only when DeepSeek fails: 1 of 151 attempts in the last run, and 14 of 160 in the first. F-10 decides if check 6 applies to the fallback ([PD11](../decisions/pd-11-launch.md)).
- **DeepSeek is slow in its peak hours.** The 95th percentile of the extractor was 6.8 to 8.3 seconds. The first run had 14 attempts that failed at the timeout of 10 seconds. A live turn then goes to Gemini. T-61 measures the composer and its deadline.
- **The misses of the last run.**
  - DeepSeek: m06 gave the food `veg` from "शाकाहारी किचन पाहिजेच", which is a must-have, in 1 of 3 repeats. e02 and e09 each gave one extra `unclear`.
  - Gemini: e03 has no `your_days` (3 of 3). h08 has no intent (1 of 3). h17 makes "tidy log hi chahiye" `unclear`, not a dealbreaker (3 of 3). e12, h13, h14, m11 and m12 leave a vague slot empty, not `unclear`.
- **The router.** h12, which is heavy Hinglish in Latin script, is `english` in 2 of 3 repeats on DeepSeek and in 3 of 3 on Gemini. Gemini calls m04 and m09, which are Devanagari Marathi, `latin`, and m15, which is heavy Marathi code-mix in Latin script, `hindi` or `mixed`.
- **The router prompt.** Its JSON shape still offers the script `mixed`, but its rule gives the script of most of the letters.
- **The set.** It has 50 sentences, and only searches. T-61 adds the other bands of the router.
